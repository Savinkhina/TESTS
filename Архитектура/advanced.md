# Kappa architecture
Каппа-архитектура (Kappa Architecture) — это шаблон проектирования систем для обработки больших данных, в котором все данные рассматриваются как единый непрерывный поток событий
Главная особенность Каппа-архитектуры заключается в том, что она **полностью отказывается от разделения на пакетную и потоковую обработку**. Вместо использования двух разных путей для исторических и «живых» данных (как это делается в классической Лямбда-архитектуре), здесь все задачи решаются внутри одного потокового конвейера (Stream Processing Pipeline).
## Как устроена Каппа-архитектура
Система состоит из двух ключевых компонентов:
- 1. Неизменяемый журнал событий (Log / Message Broker): Сюда поступают абсолютно все сырые данные в хронологическом порядке. Этот журнал служит главным источником истины и хранит значительный объем истории. Самый популярный инструмент для этого — Apache Kafka. Также могут использоваться Apache Pulsar, Amazon Kinesis или Azure Event Hubs.
- 2. Система потоковой обработки (Stream Processing Engine): Фреймворк, который непрерывно считывает данные из журнала событий, трансформирует их и сохраняет в базы данных для аналитики (уровень обслуживания). Обычно для этого выбирают Apache Flink, Spark Structured Streaming, Kafka Streams или Samza.
## Как происходит исторический перерасчет (Реиндексация)
В Лямбда-архитектуре для изменения старой аналитики запускался «тяжелый» пакетный скрипт над всей базой. В Каппа-архитектуре, если вам нужно изменить логику расчета или пересчитать исторические данные, вы просто:
- 1. Меняете код обработчика или создаете его новую версию.
- 2. Запускаете его с начальной точки (с «нулевого» смещения) в журнале событий.
- 3. Система повторно проигрывает поток исторических данных через новый код и обновляет итоговые витрины.
## Плюсы и минусы
|Преимущества (Плюсы)	|Недостатки (Минусы)|
|🛠️ Простота поддержки: один технологический стек, одна кодовая база вместо параллельных систем.	|💾 Нагрузка на хранилище: брокер сообщений вынужден хранить огромные объемы терабайтов исторического лога.|
|⚡ Низкая задержка: результаты расчетов всегда актуальны в режиме реального времени.	|⏳ Задержки при пересчете: повторное чтение гигантских массивов данных через шину потоков может занимать много времени.|
|🔄 Унификация: и текущие данные, и история обрабатываются абсолютно одинаково.	|⚙️ Архитектурные ограничения: не все сложные многопроходные алгоритмы аналитики легко уложить в модель чистого потока.|
## Сферы применения
Каппа-архитектура идеально подходит для систем, где критически важна скорость реакции и событийная модель:
- Интернет вещей (IoT) и телеметрия с датчиков.
- Мониторинг безопасности и обнаружение мошенничества (Фрод-мониторинг) в реальном времени.
- Анализ логов веб-трафика и системных аудитов.
- Платформы клиентских данных (CDP) и real-time рекомендательные системы.
